# Вывод донатов и чеки самозанятого — подготовка (14.11.2026)

Фактура собрана из официальных условий DonationAlerts (CIS Payment Terms, ред. 20.10.2026)
и документации по API.

РЕШЕНИЯ пользователя (14.11): вывод — **карта РФ** (1,9% + 20 ₽); чеки — **вариант Б
(полуавтомат)**: receipts.py ежедневно по API DA + moy_nalog, сводка в TG.

## 1. Вывод из DonationAlerts (официальные условия)

- Комиссия платформы (agency fee) с каждого доната в рублях: **12%** (если сумма донатов
  за прошлый месяц ≤ 1 млн ₽; свыше — 9%). Первый месяц после регистрации всегда 12%.
- Комиссия за ВЫПЛАТУ (сверх agency fee), способы:
  - **Карта РФ (RUB): 1,9% + 20 ₽** за транзакцию; минимум одной выплаты 150 ₽,
    максимум 50 транзакций в месяц, до 2,5 млн ₽/мес;
  - **VKPay: 0%**;
  - ЮMoney: 2,5%; мобильный счёт: 2,2%.
- Донаты в валюте конвертируются по курсу openexchangerates.org **минус 10%** — зрителям
  из-за рубежа лучше сразу видеть рублёвую страницу.
- DA старается переводить выплаты ежедневно; может задержать на период проверки
  (антифрод). В отзывах встречаются заморозки вывода на суммах от ~10 000 ₽ с запросом
  документов — выводить регулярно, не копить.
- ВАЖНО: 3 месяца без активности = статус «Inactive» и **100 ₽/день** абонентки.
  Раз в пару месяцев заходить в кабинет, если пауза в стримах.
- Рекомендуемая связка: **вывод на карту РФ (1,9%+20 ₽)** или **VKPay (0%)** — сравнить
  на первой реальной выплате; VKPay дешевле, но деньги оседают в VK-кошельке.

## 2. Налоги и чеки (НПД, самозанятость)

- Донаты от зрителей = доход от физлиц → ставка НПД **4%**. Чек нужен на каждый расчёт
  (поступление). Формировать в приложении «Мой налог» или Сбер «Своё дело».
- Спорный момент (у консультантов практики расходятся): доход считать при зачислении
  на баланс DA или при выплате на карту. Безопаснее — чек на каждый донат по факту
  поступления (видно через API DA). Компромисс, который многие используют: чек на сумму
  выплаты при выводе. Штраф за непробитый чек: 20% от суммы (первый раз обычно
  предупреждение, но лучше не проверять).
- Назначение чека: «Пожертвование/поддержка автора (донат)» — корректная формулировка
  для НПД: «Услуги по созданию контента / пожертвование».

## 3. Автоматизация чеков — варианты

Официального API у «Мой налог» нет, но есть рабочие неофициальные библиотеки
(lknpd.nalog.ru): **moy_nalog** (async Python, github.com/byBenPuls/moy_nalog),
nalogapi (sync Python), nalogovich. У DonationAlerts есть открытый API: OAuth +
WebSocket (Centrifugo) — донаты прилетают в реальном времени (scope oauth-donation-index
и т.п.).

- **Вариант А — ручной.** Раз в неделю (или после каждого стрима) открыть «Мой налог» /
  «Своё дело», пробить чеки по списку донатов из кабинета DA. Ноль кода, 5–10 минут.
  Надёжно, но забывается.
- **Вариант Б — полуавтомат (рекомендую).** Скрипт `promo/donations/receipts.py`:
  раз в день (задача планировщика) тянет донаты за сутки через API DA и формирует чеки
  через moy_nalog; итог пишет в лог и шлёт сводку в наш TG-канал от Глашатого
  («пробито 3 чека на 450 ₽»). Ошибки — в лог, дубли исключены по id доната.
- **Вариант В — полный автомат.** WebSocket-подписка на донаты в реальном времени →
  мгновенный чек во время стрима. Красиво, но: постоянный процесс, токены DA и «Мой
  налог» живут на машине, больше поверхность отказа. Реально нужно только при потоке
  донатов.

## 4. Что нужно от пользователя (для любого варианта)

1. Выбрать способ вывода в кабинете DA: карта РФ или VKPay (раздел «Мои выплаты»).
2. Для Б/В: в DA → «Приложения» создать OAuth-приложение, scope на чтение донатов
   (инструкция будет по факту, как с VK/TikTok).
3. Для Б/В: логин «Мой налог» (телефон + СМС/пароль lknpd) — библиотека хранит
   refresh-токен локально, секрет в promo/donations/ (gitignore).

## 5. План внедрения (вариант Б)

1. Кабинет DA: способ вывода + OAuth-приложение (пользователь, 15 минут).
2. `receipts.py`: auth Мой налог → список донатов DA за вчера → чеки → лог → TG-сводка.
3. Задача планировщика `Kanal15-Receipts` ежедневно 09:00 (pythonw).
4. Проверка на первом реальном донате; неделю ведём двойной учёт (скрипт + глазами).
