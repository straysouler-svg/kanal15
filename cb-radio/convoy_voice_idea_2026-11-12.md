# Идея: режим конвоя — друг в эфире «Канала 15» (12.11.2026, ТОЛЬКО ПЛАН, не выполнять)

## Концепция

Игрок запускает конвой в ETS2 (или просто едет «вместе» в Discord), друг/зритель подключается голосом
и может **разговаривать с нашими водителями** наравне с игроком. Рация в сеть НЕ подключается —
всё остаётся локально: она просто слушает второй аудиоканал и отвечает в него же.

## Как идёт голос (без единого сетевого подключения рации)

```
ДРУГ (свой ПК)                ИГРОК (наш ПК)                    РАЦИЯ
микрофон ──► Discord ──► выход Discord ──► виртуальный кабель A ──► «второй микрофон»
                                                           whisper распознаёт речь друга
                                                           
рация отвечает ──► виртуальный кабель B ──► вход Discord ──► друг слышит водителей
```

- **Виртуальные кабели**: VB-Cable / VAC — бесплатные, ставятся как аудиоустройства.
- Рация видит кабель A как обычное аудиовходное устройство — тот же код `mic.py`, второй экземпляр.
- Ответ рации миксуется в кабель B (или в стереомикшер), который назначен микрофоном Discord.
- Вариант без Discord: голосовой чат конвоя ETS2 — рация слушает loopback игры (WASAPI),
  но там голос друга смешан со звуком игры → сложнее вычленять. Discord-вариант чище.

## Почему это ложится на нашу архитектуру

1. **Разделение говорящих — бесплатно.** У каждого своё устройство ввода: физический микрофон = игрок,
   кабель A = друг. Никакой диаризации (кто сказал) не нужно — это главная сложность таких систем,
   а у нас её нет.
2. **Whisper-пайплайн готов**: тот же поток распознавания, второй инстанс с теми же intents.
3. **«По одному» уже написано** (черновик 11.11): два живых человека завалят эфир вопросами —
   отбивки «по одному» становятся ещё нужнее.
4. **Очередь ответов** уже одна (Deck): водители не перебивают друг друга, кто бы ни спросил.

## Что придётся придумать (новое)

1. **Личность друга.** Водители должны его «знать»: позывной/имя из `config.json` →
   `«convoy»: {"name": "Женя", "handle": "..."}`. Первое подключение — сценка представления
   («Мужики, у нас сегодня попутчик»). Механика `knows` распространяется на гостя.
2. **Дружба по двум журналам.** bonds.json — на игрока и на гостя отдельно
   (иначе друг наследует отношения игрока — странно и читерно).
3. **Адресация ответов.** Когда спросил друг — водитель отвечает ДРУГУ по имени.
   Когда непонятно, к кому обращаются — действующие правила addressee().
4. **Тангента друга.** У друга нет кнопки — речь по голосовой активации (VAD) на кабеле A,
   с порогом, чтобы не ловить его «бэкграунд». Помолчим/тишина распространяется на обоих.
5. **Этикет эфира для гостя.** Водители не знают его в начале: чужой → знакомый → свой,
   тот же путь, что у игрока. Сценки «кто это у нас в эфире» — новый пласт текстов.
6. **Приватность.** Гость слышит только общие реплики: личные (only_<build>, Сорока) в кабель B
   не миксуются — технически это просто второй фильтр на выходе.

## Риски и цена ошибки

- Эхо: голос рации из колонок игрока улетит обратно в кабель A → водители «слышат сами себя».
  Лечится: у игрока наушники, либо вычитание собственного выхода из входа (AEC-костыль).
- Задержка Discord (100–300 мс) — диалоги чуть ватные, для рации это даже в тему («эфир хрипит»).
- VAD ловит клавиатуру/собаку друга → ложные срабатывания. Порог + whisper-фильтр мусора.
- Нагрузка: два whisper-потока на CPU. Мерить заранее, не в день стрима.

## Этапы (каждый — отдельное одобрение)

0. **Стенд без сети**: кабель A подключён петлёй на этот же ПК (плеер с записью голоса Жени) —
   рация отличает второго говорящего, отвечает ему по имени. Песочница, не в эфире.
1. **Односторонний конвой**: друг слышит водителей и отвечает им; дружба гостю не пишется.
   Живой тест с Женей (он уже разрешал записи — хороший кандидат на первого гостя).
2. **Полный**: журнал дружбы гостя, сценки знакомства, этикет.
3. **Стрим-вариант**: зритель из чата подключается голосом (отбор через модерацию) —
   «позвони дальнобою» как формат стрима.

## Связь с именными версиями

Гость с собственным позывным = частный случай именной сборки. Реестр `handle_lines.json`
(200 строк) — та же механика v_<имя>. Конвой-режим даёт этой механике второе применение.

## Решения пользователя 12.11 (по вопросам из `convoy_review_2026-11-12.md`)

1. **Приватность: фильтровать обязательно.** Гость не слышит Сороку и личные реплики
   (`only_<build>`) — только общий эфир. Фильтр на выходе в канал гостя.
2. **Перебивка: выяснить, как работает в самой игре.** Поведение «речь гостя обрывает
   водителя / ждёт» не решать с потолка — сначала посмотреть, как ETS2 разруливает
   одновременную речь в голосовом чате конвоя, и повторить это поведение.
3. **Название: оставить «конвой», но уточнить — «онлайн-конвой».** В STATUS/логах/файлах
   использовать «онлайн-конвой» (гость голосом), чтобы не путать с «конвоем до города»
   (маршруты) и пилотом для Сороки.
4. **Звук гостя: использовать встроенную обработку голоса ETS2.** Свой радиоэффект
   для чужого потока не писать — в игре уже есть обработка голосового чата, голос
   друга придёт уже «по рации». Проверить на этапе 0, что эффект слышен.
