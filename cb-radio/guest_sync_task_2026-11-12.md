# Постановка: гость в эфире — синхронизация двух раций (12.11.2026)

Кому: Штурману → Механик (код), Испытатель (проверка). Летописцу пока ничего.
Основание: решения пользователя 12.11 (см. `prompts/convoy_review_2026-11-12.md`, разделы 8–9) и его слова: «пиши промт для команды по пунктам 1 и 2, пункт 1 как тест на 1 машине, нет возможности с Женей поиграть».

## Решения пользователя, на которых стоит задача

- Друг слышит **водителей игрока** (не своих).
- Правило «рация в сеть не выходит» для режима гостя **снято пользователем** — но только для этого режима и только по шагам ниже.
- Голоса живых людей — в голосовом чате игры; рация передаёт **не звук, а события** («актёр X, файл Y, расстояние Z»). Каждая рация играет файлы из своей установки.
- Транспорт — **сменная деталь**: сейчас локально, потом Steam.

## Архитектура (кратко, для Механика)

- **Хозяин** (рация игрока) — единственный источник решений: Operator, Deck, дружба, настроение, трасса работают как сейчас.
- **Гость** (рация друга) — тонкий клиент: не выбирает реплики, только проигрывает присланное и отправляет вверх своё.
- События вниз (хозяин → гость): `play` (относительный путь из белого списка/ID, актёр, расстояние), `stop`, `ptt` (хозяин нажал — гость глушит эфир).
- События вверх (гость → хозяин): `ptt` (гость нажал/отпустил), `said` (распознанный текст гостя).
- Точки вставки в коде (проверено): весь звук водителей проходит через `Player.file` / `Player.item` / `Player.street` (cb_radio.py:1196, 1272, 1247); распознанная речь — `Ears.results` (cb_radio.py:1436).
- Модуль `transport.py` с интерфейсом «отправить событие / получить событие / подключиться / отключиться». Первая реализация — TCP на 127.0.0.1. Никакой логики эфира внутри транспорта.

## Этап 1 — синхронизация на ОДНОЙ машине (делать сейчас)

Цель: доказать, что гость слышит те же реплики, что хозяин, его «тангента» обрывает эфир у обоих, а его фраза доходит до хозяина и водитель отвечает. Всё на ПК пользователя, без второго человека и без интернета.

### Как поднять вторую рацию на одном ПК (узлы в коде, проверены)

1. **Блокировка второго запуска.** `single_instance(cfg["lock_port"])` (cb_radio.py:2629, 2993) не даст запустить вторую копию с тем же портом. У гостя — свой `lock_port` в его config.json.
2. **Всё состояние лежит рядом со скриптом** (`ROOT`, cb_radio.py:46–56, 180–181, 980, 3285): config, state, bonds.json, quest_state, логи. Значит, гость = **отдельная папка** (например `build/_guest/`), не трогающая основную. Аудио (`audio/`, ~3400 файлов) — не копировать, а подключить junction-ссылкой. Бэкап перед созданием не нужен: основная папка не меняется — но проверить это первым делом.
3. **Прочие порты** (оверлей, всё, что слушает сокеты) — найти и развести, чтобы копии не конфликтовали.
4. **Тангента гостя** — отдельная клавиша клавиатуры (основная остаётся на руле). Иначе одна кнопка включит обе рации.
5. **Голос гостя без второго whisper.** Вторая модель — ещё ~2,2 ГБ рядом с игрой. Для этапа 1 у гостя распознавание выключено (`mic.enabled=false`), а фраза гостя вводится **отладочным способом**: файл/консоль «сказать как гость: <текст>» → событие `said`. Whisper гостя проверяется отдельно позже.
6. **Звук гостя** — на другое устройство вывода (например, наушники при колонках у хозяина), чтобы на слух различать, кто что играет. Если второго устройства нет — достаточно журнала.

### Что сделать

1. `transport.py` (интерфейс + TCP-реализация на 127.0.0.1), режим запуска `--guest <адрес>`; хозяин включает приём по пункту в меню значка (по умолчанию ВЫКЛ).
2. Хозяин: в трёх точках `Player` — отправка `play`/`stop`; приём `ptt`/`said` от гостя.
3. Гость: проигрывание по `play` через существующий `Player.file` (с его радиоэффектом), без Operator/Deck; если файла нет в установке гостя (`variant_of` → None, личные `only_<build>`, Сорока) — тишина и строка в журнал, НЕ ошибка.
4. Фраза гостя у хозяина проходит тот же разбор интентов, что фраза игрока, но **помечена источником `guest`**. Дружба гостю на этапе 1 **не пишется** (bond_add не вызывать для `guest`). Адресация по имени — не делать, отвечают как игроку.
5. Тангента любой стороны обрывает реплику у обеих.
6. Журнал: строки гостя — с той же разметкой, что у тангенты игрока, чтобы `_hide_speech` (cb_radio.py:2849) прятал их в отчёте. Голос гостя на диск не писать.

### Безопасность (обязательно, даже для локального теста)

- `play` принимает только ID/относительный путь, который есть в списке фраз установки; абсолютные пути, `..`, чужие расширения — отбрасывать. Никакого `eval`/исполнения из сети.
- Порт слушает только 127.0.0.1 на этапе 1.
- Размер сообщения ограничен; битое сообщение — строка в журнал, рация живёт дальше.

### Приёмка (Испытатель)

- Хозяин и гость запущены одновременно, основная папка после теста не изменилась (сверить хэши config.json, bonds.json, state.json до/после).
- 20 минут заезда: число `play` у хозяина = числу проигранных у гостя (минус отсутствующие файлы, перечислить какие).
- Тангента хозяина и тангента гостя обрывают эфир у обоих; задержка на глаз — без заметной паузы.
- 10 фраз «как гость» (приветствие, «кто в эфире», «повтори», «помолчим», вопрос конкретному водителю) — ответ приходит, у обоих звучит одинаково.
- Отключение гостя посреди реплики — хозяин работает дальше, ошибок в cb_radio_errors.log нет.
- Хозяин с выключенным режимом гостя ведёт себя ровно как 1.33 (регресс).

## Этап 2 — Steam через тестовое приложение Spacewar (AppID 480) — ТОЛЬКО ПОДГОТОВКА

Цель: вторая реализация `transport.py` через сеть Steam, без своего AppID и без взноса $100.

1. **Сначала документация, потом код.** Сверить с официальной документацией Steamworks: допустимо ли использовать AppID 480 для теста P2P, какой интерфейс брать (ISteamNetworkingSockets / ISteamNetworkingMessages), как работает соединение по SteamID друга и ретрансляция Valve. Утверждение «480 подходит для тестов» — по памяти внешнего ревьюера, не факт. Ссылки и дату сверки — в отчёт.
2. Выбрать Python-обвязку Steamworks (или минимальный ctypes к steam_api64.dll), оценить зрелость, лицензию, совместимость с текущей сборкой exe.
3. Реализация за тем же интерфейсом, что TCP; переключение в config (`guest.transport: "tcp" | "steam"`).
4. **Живой тест этапа 2 сейчас невозможен:** нужны два аккаунта Steam на двух ПК, второго человека нет. На одном ПК Steam-клиент один — соединиться сам с собой не получится. Поэтому этап 2 = код + модульные проверки + письменный план живого теста; сам тест — когда появится второй участник (Женя или другой). Не имитировать «проверено».
5. Никаких покупок, регистраций, ввода данных карт и аккаунтов — только пользователь сам.
